# 硬幣對戰 V0.1

原生 HTML、CSS、JavaScript 的可遊玩單機原型，介面採繁體中文。不依賴第三方套件、外部圖片、字型或網路服務。

## 手遊介面版本

採米白背景、藍灰按鈕與系統黑體的極簡直向設計，桌機也以最高 560px 寬的直向遊戲畫面呈現。底部固定五個入口：首頁、對戰、抽卡、收藏、編隊；鍍膜收藏位於收藏內的分頁。戰鬥頁以返回／主要操作列取代底部導覽。

- 首頁恢復硬幣主視覺、大型對戰按鈕、五個功能入口與出戰準備摘要，保留極簡配色。
- 金色正面與紫色反面硬幣搭配低彩度鍍膜內色；結算直接顯示比分與三局勝負表。
- 收藏採三欄小卡，點選開啟詳情；編隊採單欄裝備操作，保留底部安全區。
- 抽卡機率收在可展開面板，結果以獨立畫面呈現，確認後返回抽卡。
- 保留原有戰鬥規則與存檔格式，無需重置收藏。已加入可安裝的 PWA 支援，尚未打包為原生 iOS／Android App。

編隊操作已改為「點選上方位置 → 更換硬幣 → 分別配置兩面鍍膜」。滿編時可直接換入新硬幣；選擇已入隊的硬幣則交換位置。點擊正面或反面的「更換鍍膜」，會展開鍍膜卡片供選擇，顯示攻擊加成與目前裝備位置。兩面各有基礎傷害、鍍膜加成與攻擊小計（尚未計入對手的五行關係）。移出隊伍不刪除收藏或卸下鍍膜；空缺位置會依序補入。

遊玩硬幣外圈固定區分正反面：正面為金色、反面為紫色，攻擊數字也與外框同色。內部顏色由該面的鍍膜決定：金為淡金、木為綠、水為藍、火為紅、土為棕，無鍍膜為灰色。硬幣本身只顯示傷害數字，文字明細位於外部。

首頁與戰鬥頁使用 `100dvh` 可視高度，完整配置於單一畫面，字體恢復系統黑體。首頁主視覺依可用高度伸縮，保留對戰按鈕、功能入口與出戰準備摘要。戰鬥頁包含回合牌、兩側干涉次數、中央比分、雙方硬幣、精簡戰力、干涉與主要操作。備戰卡只在選幣階段顯示，選好後按「開始擲幣」；擲幣前敵方選幣保持隱藏。結算階段集中顯示勝負結果。首頁和戰鬥所有階段皆不需要捲動，規則與紀錄改為按鈕開啟獨立面板。收藏等長清單於自己的內容區域捲動，頁面外框保持固定。

## 啟動

直接用 Chrome、Edge、Firefox 或 Safari 開啟 `index.html` 即可。無需安裝或建置。

若要用固定網址保存進度，或從同網路手機開啟，可於本目錄執行 `python -m http.server 8080`，電腦開啟 `http://localhost:8080`，手機開啟 `http://電腦區域網路IP:8080`（需允許本機防火牆）。伺服器只提供靜態檔案，遊戲沒有後端。

收藏、代幣及編隊儲存在瀏覽器的 localStorage。不同瀏覽器、網址、連接埠或檔案位置可能使用不同存檔；私人模式或封鎖儲存時可能無法保留。進行中的對戰不保存，重新整理將返回備戰。

## 遊玩

1. 初次提供硬幣 A（3/3）、B（1/10）、C（5/7），六片單面測試鍍膜，3,000 代幣；已完成初始裝備與編隊。
2. 在召喚工坊選擇硬幣或鍍膜池，進行單抽或十連。每抽 100 代幣，免費補給可不限次領取。
3. 在編隊頁點選上方隊伍位置，再按「更換硬幣」選擇收藏，或點擊兩面的「更換鍍膜」選擇鍍膜卡片。滿編可直接替換，已入隊硬幣則交換位置。裝備使用中的鍍膜會轉移至指定面。
4. 進入競技場，開始對戰。每局點選尚未出戰的備戰硬幣，再按「開始擲幣」，擲幣後決定保持或干涉翻面，再進入下一回合。
5. 打完三局後依勝分比較；勝分相同則比較累積最終戰力，仍相同則整場平手。

## 規則與調整

每片鍍膜只有 `element`（一種五行）與 `attack`（整數 +0～+5）。每抽獲得一片，十連獲得十片；屬性與攻擊力獨立抽取，預設五行各 20%、六種攻擊值各 1/6。權重集中在 `js/config.js` 的 `elementWeights` 與 `coatingAttackWeights`。

硬幣以 `frontCoatingId`、`backCoatingId` 分開裝備，單片可用在任一面，但同時只能占一個槽位。轉移或卸下不消耗道具。三枚出戰硬幣共六個面必須裝滿；初始提供六片測試鍍膜（攻擊 +0）。

最終戰力 = 當前面基礎傷害 + 當前面鍍膜攻擊力 + 五行加成。翻面後改用另一面的屬性與攻擊力，AI 使用相同規則。

存檔格式升為 version 2，沿用原 localStorage key。舊版每個雙面鍍膜拆成兩片，正面片保留原 ID，反面片取得新 ID，兩片繼承原攻擊力（舊資料缺少時補 +0）；裝備關係自動對應到兩面，代幣與編隊不變。再次載入不會重複拆分。

硬幣總傷害 6–12 的權重預設各 1；先抽總傷害，再於 1 到總傷害減 1 間均勻抽正面，剩餘為反面。單抽與十連使用同一規則。

光與暗沒有數值加成；克制方 +2，受到相生方 +1，同屬性無加成。單局平手各得 0.5 分。

AI 在玩家選幣前隨機鎖定自己的剩餘硬幣。擲幣後、顯示干涉按鈕前，AI 已鎖定干涉決定：翻面能改善戰力差，且當前未領先或已是第三局時，使用尚餘的一次干涉。玩家的干涉選擇不參與 AI 決策。開場會複製編隊，途中更改收藏裝備不影響該場對戰。

這是本機原型，使用 Math.random，資料及 AI 的秘密決定不具備抵抗開發者工具檢視或修改的安全性。

## 驗證

於本目錄執行：

```sh
node --test tests/game.test.cjs
```

測試涵蓋數值邊界、十連扣款與獨立 ID、鍍膜轉移、25 種五行對局、100 場完整三局、AI 預先承諾、干涉與使用次數限制、平分決勝、存檔，以及模擬 DOM 操作的抽卡到結算流程。模擬 DOM 測試不等同實際瀏覽器視覺與觸控測試。

已使用本機 Chrome 的手機尺寸模擬檢查：320×568、360×640、390×700、390×844、430×800、1024×768；首頁、抽卡、抽卡結果與全部戰鬥階段皆檢查頁面及主要內容高度沒有超出可視範圍，並實際操作完整三局至結算、驗證規則／紀錄面板與系統字體。可用 Node 24 執行 `node tests/browser-check.cjs` 重跑；預設使用 Windows 已安裝的 Chrome，可用 `COIN_DUEL_CHROME` 指定其他 Chrome 路徑。此檢查使用獨立暫存設定檔，截圖寫入不納入版本控制的 `.qa/`，不會讀取個人瀏覽器設定檔。仍未測試實體手機觸控、iOS Safari 與 Android 系統差異。

## 存檔備份

右上角選單 → 存檔管理，可立即儲存或匯出 JSON 檔案。重開進度消失時，選擇備份檔案，核對收藏數量後按「確認載入此存檔」。載入會取代目前收藏、代幣與編隊，結束進行中的對戰。匯入前先驗證資料；無效檔案不會覆蓋進度。本機存檔讀取失敗時停止自動寫入，以保護原始資料。

自動儲存仍依賴同一瀏覽器與網址的 localStorage；無痕／暫存瀏覽器或清理資料可能讓進度消失，建議定期匯出。存檔不含進行中的對戰。

## GitHub Pages 與手機安裝

將 `coin-duel` 內的全部檔案（包含 `assets`、`js`、`manifest.webmanifest`、`sw.js`）上傳至 GitHub Pages 發布目錄，再啟用 Pages。可放在網站根目錄或專案子路徑，所有資源皆使用相對路徑。

使用 Pages 提供的 HTTPS 網址開啟遊戲，右上選單 → 安裝到手機。Android Chrome 可使用安裝按鈕或瀏覽器選單；iPhone Safari 使用分享 → 加入主畫面。首次連線顯示「離線內容已準備完成」後，才能離線開啟。直接開啟 HTML 或手機以區網 HTTP IP 開啟不支援此安裝流程。

收藏、代幣與編隊仍在每次操作後自動儲存，不需要手動匯出。安裝頁可請求瀏覽器長期保留資料；授權由瀏覽器決定，不保證避免手動清除或跨裝置同步。從本機檔案搬至 Pages 網址會使用不同儲存空間；如需搬移原有進度，可使用一次匯出／匯入。

每次發布程式更新時，請遞增 `sw.js` 的快取版本（例如 `coin-duel-shell-v2`）。新版本在舊遊戲視窗全部關閉後啟用，避免對戰途中混用不同版本。程式快取更新不會刪除 localStorage 進度。

新增檔案：`manifest.webmanifest`（App 設定）、`sw.js`（離線快取）、`js/pwa.js`（安裝與儲存保留請求）、`assets/icon-192.png` 與 `assets/icon-512.png`（安裝圖示）。

`node --test --test-isolation=none tests/game.test.cjs tests/pwa.test.cjs` 共 22 項測試已通過，包含專案子路徑、快取清單及模擬離線回應。`node tests/pwa-check.cjs` 提供完整 Chrome 關閉重開、離線與可安裝性測試；此次執行未獲啟動權限，尚未確認此測試與實機安裝結果。
